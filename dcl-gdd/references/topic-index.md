# Find the relevant design reference

**Load for the current question, even outside the section route.** Before giving specialist advice,
read the matching reference below unless already loaded; take only the relevant block. Do not
read the whole library, turn it into an agenda, or wait for a later stage to use it.

| Current question | Reference |
|---|---|
| Core action, choices, boredom or repetition | [core-experiments](core-experiments.md) |
| Mood, expression, attention or what a metric means | [experience-prompts](experience-prompts.md) |
| Horror, dread, suspense or testing an intended scare | [horror-playbook](horror-playbook.md) |
| Challenge, failure, novice/expert advantage | [challenge-experiments](challenge-experiments.md) |
| Sensation, space or a different presentation of the fantasy | [feel-experiments](feel-experiments.md) |
| Latency, input/state, measurements or a numerical design benchmark | [feel-instruments](feel-instruments.md) |
| Questions for players, survey timing or interpreting their answers | [player-feedback](player-feedback.md) |
| Audience, communities, first players, sharing or preparing promotion | [acquisition](acquisition.md) |
| Finding and comparing candidate communities, for a game or before one | [audience-discovery](audience-discovery.md) |

Before writing or revising an IP status, load the [IP self-check](scope-and-evidence.md#ip-and-content-declaration--now-a-header-self-check), even for a header-only edit.

Read only the blocks needed for the current question. Your successful write is current state;
re-read when another actor may have changed it or a claim needs checking. Program-specific
sections in references apply only on the chosen proposal route; their quotas and benchmarks
are not universal requirements for game design.

- [references/hypothesis-log.md](hypothesis-log.md) — the Log's contract: what it is and
  who owns which fact, one file per operation in [references/hypothesis-log/](hypothesis-log/)
  — parking (with `ideas.md`, `implementation-notes.md`, `decisions.md`), files and IDs, index
  rebuild, the handoff vehicle, verdicts.
- [player-promise](player-promise.md) · [core-loop-and-ftue](core-loop-and-ftue.md)
  — explaining the intended experience, action, feedback and first encounter.
- [retention](retention.md) · [social-design](social-design.md) ·
  [mobile-first](mobile-first.md) — when return visits, company or touch matter to
  the owner's goal. A single-visit experience or intentional group-only game can be the goal.
- [creator-success.md](creator-success.md) — the complete optional proposal workflow,
  including its template, section map, progress, stage gates and submission references.
- [references/design-lenses.md](design-lenses.md) — questions, alternative explanations and small
  experiments; agent-side guidance that never adds a field.
- [references/playbook.md](playbook.md) — standing rules, platform fit, success
  criteria, voice. The **provenance of any number** is checked before quoting
  a benchmark at an owner — the retention canon is `retention.md#benchmarks`.
- [platform capability map](platform/dcl-capability-links.md) — game needs,
  implementation candidates and platform services in the maintained reference bundle,
  with scoped evidence and primary sources. Reuse applicable findings; investigate remaining gaps
  through platform-fit rather than treating every dated entry as expired.

The last two are internal: creators never see them.
