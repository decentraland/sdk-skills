# Avatar Animation Catalog — built-in emotes + Creator Hub Avatar Animations pack

Ready-made avatar animations for the **player** (`triggerEmote` / `triggerSceneEmote`, API in **player-avatar**) and for `AvatarShape` NPCs (**npcs**). Check here **before** authoring a custom clip in Blender. Order of preference:

1. **Built-in emote** (section 1) — play by name, nothing to download, works in every scene. 32 names, plus 5 embedded-only ids.
2. **Avatar Animations pack file** (section 2) — 45 `_emote.glb` clips from the Creator Hub asset packs, available to every Creator Hub user. Download into the scene and play with `triggerSceneEmote`.
3. **Custom clip** — only when neither fits: author it on the official rig (**avatar-animations** SKILL.md).

Search: `grep -i "keyword" animation-catalog.md`. Every row ends with an animated `preview:` (looping .webp) — fetch it to look at the motion before choosing. Both kinds need `ALLOW_TO_TRIGGER_AVATAR_EMOTE` in `scene.json` `requiredPermissions`.

## 1. Built-in emotes (play by name)

```typescript
import { triggerEmote } from '~system/RestrictedActions'
triggerEmote({ predefinedEmote: 'wave' })               // one-shot
triggerEmote({ predefinedEmote: 'sittingChair1' })      // loops: holds the pose until stopEmote({}) or the player moves
```

These 32 ids are the ones the Creator Hub lists as **Built-in** (its *Play Default Emote* action and the Avatar Animations pack). `Loop` = holds the pose indefinitely; the others play once and return to idle. *Embedded* ids ship inside the Explorer binary; *social* ids resolve as emote URNs (need the content server, like any wearable emote). Ids are case-sensitive. Loop flags and the 5 embedded-only ids (`crafting`, `handsintheair`, `Victory`, `Waving`, `fistpump_short`, not listed by the Creator Hub) are verified in `embedded-emotes.md`, the single source of truth for the embedded set. The 16 social ids are one-shot gestures and dances; their loop flag is not verified against the Explorer asset.

## 2. Avatar Animations pack — downloadable `_emote.glb` clips (45)

**Download** with the `dl-asset.mjs` helper in `{baseDir}/../add-3d-models/references/model-patterns.md` (run from the scene root): `node dl-asset.mjs <id>` writes the file to `assets/asset-packs/<folder>/<file>` — the same path the Creator Hub uses when the user drags the animation from its catalog onto the viewport (which adds the file only, no entity). A plain `curl -o <file path> <glb url>` also works: each row's `glb:` url is the single file. Keep the `_emote.glb` suffix and play it with the exact on-disk path:

```typescript
import { triggerSceneEmote } from '~system/RestrictedActions'
triggerSceneEmote({ src: 'assets/asset-packs/dance/Avatar_Dance_emote.glb', loop: false })
triggerSceneEmote({ src: 'assets/asset-packs/puff_-_idle_1/Puff_Idle_01_fix_emote.glb', loop: true })  // idle/sitting poses: loop
```

- **Loop** is your call at trigger time (`loop: true`): use it for the `sitting` rows and any `idle` clip; one-shots (`actions`, `expressions`) play through once. Clip lengths are exact (30 fps), so a one-shot's end can be timed from `dur` when `AvatarEmoteCommand` events are not available (masked emotes).
- **`clips: 2` rows carry a prop** (mallet, marshmallow stick, watering can, cup): the second clip animates the prop that is bundled in the same file — nothing extra to place. They are larger (0.6–2.3 MB, under the 3 MB cap).
- Through the Creator Hub MCP, `place_smart_item` **rejects** these ids (file-only assets): ask the user to drag the card from the catalog, or download the file as above and reference it from code.
